## 1. 목표

지도 탐색 동 패널에서 사용자가 그 동네에 대해 **채팅으로 이어서** 묻는다. 대화 중 같은 시군구의 다른 동네 이름이 나오면 그 동네까지 그래프에서 조회해 **비교**하고, 사용자 기준(관심 기록·기준 칩)에 맞춘 **상황별 안내**("조용한 환경이 우선이면 효자2동이 맞아요")로 답한다.

완료 기준:

- `POST /api/explore/chat` 이 §8 형식으로 답하고, 같은 `conversationId` 로 이어지는 질문이 직전 동네·의도를 이어받는다.
- 비교 답의 모든 문장은 **방향 검사**(§6-2)를 통과했거나 규칙 문장으로 바뀌어 있다. 틀린 방향의 문장이 응답에 나가지 않는다.
- 답에 숫자·등급이 나오면 사실과 일치한다(v6 `validate_sentence`).
- 비교 답 프롬프트에는 사용자 문장이 들어가지 않는다(대표 질문 + 코드 정리만). 동 1개 답은 지금 v6.1 코드대로 질문을 넣는다(2026-11-13 결정).
- HCX 키가 없거나 실패해도 규칙 문장으로 답한다. Redis 가 죽어도 질문 하나하나에는 답한다.
- `uv run pytest` 가 Redis·Neo4j·HCX 없이 통과한다.

## 3. 흐름 (LangGraph)

```
START
  → load_context      체크포인트에서 패널 동·비교 동네·직전 의도를 읽는다 (LangGraph 가 자동)
  → resolve_dongs     질문 속 동 이름 → 패널 동과 같은 시군구 사전에서 찾기 (§4)
  → find_intent       임베딩 → ask_vocab (v6.1). 못 찾았고 동 이름이 있으면 직전 의도 이어받기(없으면 비교 중 compare_summary), 동 이름이 없으면 안내
  → route ─┬─ guide           unknown_* · 다른 시군구 · 동 1개에 compare_summary → 안내 문구 → END
           └─ fetch_graph     동마다 fetch_dong + 공통점·축별 순서·닮음 정리 (§5)
                → route_mode ─┬─ single_answer   동 1개: v6.1 ask.answer 그대로
                              └─ compare_answer  동 2~3개: HCX-007 SO (§6-1)
                → verify      숫자·금지어·방향·문장 속 이름 (§6-2) → 실패 문장만 규칙 문장
                → evidence    근거 줄 생성 (§6-3)
                → END
```

- 노드는 `explore/chat/` 의 순수 함수로 두고, 그래프 조립은 `explore/chat/graph.py` 한 곳에서 한다. 노드 함수는 LangGraph 없이 단위 테스트한다.
- 상태(`ChatState`, TypedDict):

| 필드 | 형 | 설명 |
| --- | --- | --- |
| `question` | str | 이번 질문. HCX 로 보내지 않고, 마지막 노드에서 비워 체크포인트에 남기지 않는다(§7-2-1) |
| `panel` | str | 패널 동 행정동 코드 |
| `dongs` | list[str] | 이번 턴 비교 대상 (1~3) |
| `intent` | str | 이번 턴 의도 |
| `criteria` | dict | 칩 + 관심 기록 요약 (§5-3) |
| `facts` · `orders` · `common` · `likeness` | — | `fetch_graph` 결과 |
| `sentences` | list[dict] | `{text, evidence, source}` |
| `turns` | list[dict] (누적, `operator.add`) | `{intent, dongs}` 최근 기록. 의도·동네만 |

## 4. 비교 대상 동네 정하기

1. 기준은 항상 패널 동이다. 패널 동이 바뀌면 웹이 새 `conversationId` 를 받는다.
2. 질문에서 동 이름을 찾는다. 사전은 **패널 동과 같은 시군구의 동 이름**(약칭 포함, 예: "효자2동"·"효자 2동"). 찾으면 `[패널 동, 찾은 동…]`.
3. 이름이 없으면 직전 턴의 `dongs` 를 이어받는다("주말엔?").
4. 새 이름이 나오면 비교 대상이 그 동으로 바뀐다("그럼 교1동은?" → `[패널 동, 교1동]`). "셋 다"·"둘 다" 류 표현이면 앞서 나온 동까지 최대 3개.
5. 다른 시군구 동 이름(전체 203동 사전에는 있으나 같은 시군구에 없음)이면 `guide`: "지금은 같은 시군구 안의 동네끼리만 비교할 수 있어요. {시군구}에서는 {동 2~3개} 등과 비교해 볼 수 있어요." 시군구 이름만 나오면 "동네 이름으로 물어봐 주세요".
6. 4개 이상 나오면 앞의 3개만 쓰고 안내 한 줄을 붙인다.

## 5. 의도 · 그래프 조회 · 사용자 기준

### 5-1. 의도

v6.1 의도 14개(답할 수 있는 10 + `unknown_*` 4)에 둘을 더한다. `ask_vocab` 에 표현 약 20개를 추가한다(사전 버전이 바뀌어 의도 캐시는 자동 갱신).

| 의도 | 동 1개 | 동 2~3개 |
| --- | --- | --- |
| `quiet` `peer` `evening` `type` `coast` `life` | v6.1 그대로 | 축별 순서로 상황별 안내 |
| `weekday_hours` `weekend_hours` | v6.1 그대로 | 한 문장에 견줌 ("주말엔 A가 11시, B가 14시에 차가 가장 많아요" · 같으면 "A·B 모두"). 평일은 업무시간 한산 시각도. 주말 한산 시각은 쓰지 않는다(§11) |
| `months` | v6.1 그대로 | 같은 시군구라 항상 공통점("둘 다 ○·○월이 한산해요") |
| `similar` | v6.1 그대로 | `similarity` 와 같게 처리 |
| `compare_summary` (신규) | 안내: "다른 동네 이름과 함께 물어봐 주세요" | 사용자 기준 축 2~3개로 상황별 안내 |
| `similarity` (신규) | `similar` 로 처리 | 닮음 백분위 + 공통점 |

추가 표현 예: 비교해 줘 · 둘 중 어디가 · 뭐가 달라 · 어디가 더 나아 · 둘이 비슷해 · 차이가 뭐야 · 셋 중엔.

### 5-2. 그래프 조회와 정리 (`fetch_graph`)

동마다 `queries.fetch_dong(code)`(정해진 Cypher, 1칸 + 시군구 EASE + SIMILAR)를 부르고 코드가 정리한다.

| 정리 | 만드는 법 | LLM 입력 예 |
| --- | --- | --- |
| 공통점 | `common_facts` 를 n개 동으로 넓힘(같은 노드에 연결, 차수 낮은 것 먼저) | `공통: 로컬살이형 1위 · 전주시 한산한 달 1·2·8월` |
| 축별 순서 | 축마다 값으로 정렬. 동점이면 "같음" | `조용함 높은 순: 효자2동(S) > 여의동(A)` |
| 연결 | 비교 동끼리 `SIMILAR`, 최근 본 동과 `SIMILAR` | `여의동은 효자2동과 비슷한 동 2위` |
| 닮음 | `metric_vec`(연간) L2 → 같은 바닷가 여부 동끼리 전체 쌍 분포의 백분위 → 3구간 | `두 동네 닮음: 가까운 편` |

- 등급·점수는 그래프 연간 값을 쓴다. 동 패널도 같은 연간 값이라 화면과 어긋나지 않는다(월 선택 없음).
- 원래 숫자는 근거 줄(§6-3)에만 쓰고, LLM 입력에는 등급과 순서만 넣는다.

### 5-3. 사용자 기준 → 비교 축 (`compare_summary`)

웹이 보내는 `criteria = {chips: [...], interest: {metric, terrain, recent}}` 에서 위부터 채워 축 2~3개를 고른다. 같은 축은 한 번만.

1. 기준 칩(사용자가 고른 것)
2. 관심 기록 지표 관심 상위 1~2 (`metric`)
3. 관심 기록 지형: 바다 → `coast`
4. 최근 본 동(최대 3)이 비교 동과 `SIMILAR` 로 이어져 있으면 연결 문장 1개
5. 아무 기준이 없으면 비교 동끼리 등급 단계 차가 큰 축부터

칩 목록: 조용함 · 또래 · 저녁 활기 · 바다 · 몰입형 · 네트워킹형 · 로컬살이형. 서버는 칩 키를 허용 목록으로 검증한다.

## 6. 답 생성 · 검사 · 근거

### 6-1. 생성 (`compare_answer`)

- `ChatClovaX(model="HCX-007", thinking={"effort": "none"}, temperature=0.3, max_tokens=512)` 에 `with_structured_output(CompareAnswer, method="json_schema")`.
- 스키마: `sentences` 2~3개, 각 `{text: str, axis: Literal[이번 턴 축들]}`. **`direction` · `pick` 은 받지 않는다**(direction 은 실측에서 "낮다"로 적어 검사를 빠져나감, pick 은 2026-11-17 로컬 확인에서 문장은 맞는데 pick 칸만 틀리는 일이 잦아 뺌). 고른 동은 문장 속 동 이름으로 본다. 상황 문장은 "그 축이 높은 쪽을 원하면"으로만 쓴다.
- 프롬프트에는 사용자 문장 대신 의도의 대표 질문, 사용자 기준(칩·관심 이름), §5-2 정리만 넣는다.
- 시스템 지시: 상황별 안내 형식, 해요체 60자, 숫자 금지, 문장마다 다른 축, 이름에서 받는 인상(면=시골=조용) 금지, 금지어·전문 용어 금지.
- 시간 제한 10초, 재시도 없음(실패 → 규칙 문장).

### 6-2. 검사 (`verify`) — 하나라도 걸리면 그 문장만 규칙 문장

| 검사 | 내용 |
| --- | --- |
| 방향 | 문장 속 동이 축별 순서의 단독 1등인가(동점 1등 포함 안 함) |
| 이름 | 문장 속 비교 동 이름이 정확히 하나. 없거나 둘 이상이면 실패 |
| 숫자·등급 | v6 `validate_sentence` (동 이름 속 숫자는 제거 후 검사) |
| 금지어 | `brief.BANNED` + 전문 용어(지표·벡터·거리·백분위·노드·그래프·데이터) |
| 모양 | 끊긴 문장(해요체 종결 없음), 같은 축 중복, "두 곳 모두" 류 결론 없음 |

- LLM 문장은 문장마다 문형을 다르게(프롬프트 c3). '반면'·'대신' 은 앞 문장과 다른 동네일 때만 남긴다(`_fix_contrast`). 답 문장은 끝에서 합쇼체 → 해요체, 마침표를 맞춘다(`tidy`). 공통점은 "둘 다 바닷가에 있고, 조용함 수준이 같아요." 처럼 문장으로(등급 글자 · 시각별 한산 제외).
- 규칙 문장: `{축 이름}을 원한다면 {1등 동}이 맞아요.` (`brief.josa` 적용). 축 1등이 동점이면 "{축 이름}은 두 동네가 같은 등급이에요."
- 동 1개 답은 v6.1 검사(`ask.check_sentence`)를 그대로 쓴다.
- 응답 `source`: `llm`(전부 통과) · `mixed` · `rule`. 비율을 로그로 남긴다.

### 6-3. 근거 줄 (`evidence`)

코드가 축 값에서 만든다: `조용함: 효자2동 S · 여의동 A`. 닮음은 `두 동네 닮음: 전국 동네 쌍 중 가까운 쪽 20%`. LLM 출력은 쓰지 않는다.

## 7. 저장 · 캐시 · 운영

### 7-1. Redis 8 과 체크포인터

- `compose.yaml` 의 `redis:7` → `redis:8` (JSON·검색 내장). 배포 Redis 도 8 로 잡는다. 실측: redis:7 은 `FT.INFO` 없음으로 시작 실패, redis:8 은 대화 이어짐·TTL 동작.
- `RedisSaver.from_conn_string(REDIS_URL, ttl={"default_ttl": 30, "refresh_on_read": True})`, 앱 시작 시 `setup()` 한 번.
- 저장량: 기본 설정은 노드마다 상태 전체 저장(시험 상태 3턴에 키 40개·약 63KB). `durability="exit"` 로 실행 끝에만 저장해 줄인다(§7-2-1). `maxmemory 256mb allkeys-lru` 에서 오래된 대화부터 지워진다 — 30분 대화 기억과 맞는 동작으로 본다.
- **Redis 장애**: 체크포인터 그래프 실행이 Redis 오류로 실패하면 체크포인터 없이 컴파일한 같은 그래프로 한 번 더 실행한다(이어받기만 빠짐). `REDIS_URL` 이 없으면(로컬·테스트) `InMemorySaver`.

### 7-2. 답 캐시

| 무엇 | 어디 | 키 |
| --- | --- | --- |
| 질문 → 의도 | Redis 30일 (v6.1) | 정규화 질문 + 사전 버전 |
| 동 1개 답 | Redis + Postgres `dong_answer` (v6.1) | 동 + 의도 + 사실 해시 |
| 동 2~3개 답 | Redis **1일** | 정렬한 동 코드 + 의도 + 고른 축 + 정리 해시 + 모델 + 프롬프트 버전 |

- 비교 답 캐시는 대화에 필요한 저장이 아니라 같은 비교를 다시 물을 때 HCX 호출을 줄이는 용도다(시연 안정성 포함). 그래서 1일로 짧게 둔다(사용자 결정).
- 키에 사용자 문장은 들어가지 않는다(의도·축만). 개인화는 "고른 축"으로만 들어가 같은 기준이면 캐시가 맞는다.
- 프롬프트 버전이 키에 있어 문구를 고치면 바로 새 답이 나간다.
- 비교 답은 Postgres 에 저장하지 않는다(`dong_answer` 는 동 하나 기준 표).

### 7-2-1. 질문 원문을 남기지 않기

- 체크포인터는 상태 전체를 저장하므로, 그래프 실행은 `durability="exit"`(끝날 때만 저장)로 하고 마지막 노드에서 `question` 을 빈 값으로 둔다. 대화 기억에는 의도·동네만 남는다.
- 질문 → 의도 캐시는 질문 해시만 키로 쓴다(v6.1).
- 결과: 서버 저장소 어디에도 사용자 질문 원문이 남지 않는다. 대화 기억은 30분 뒤 사라진다.

### 7-3. 남용 방지 · 장애

- throttle: v6.1 그대로 IP당 10회/분 · 200회/일 (`explore_ask_burst` · `explore_ask_day` 설정 복원).
- HCX 실패·키 없음 → 규칙 문장. Neo4j 장애 → 503 안내(v6.1 과 같음).
- 질문 100자 제한(v6.1).

### 7-4. 패키지

`langgraph` · `langgraph-checkpoint-redis` · `langchain-naver`(= `langchain-openai` · `openai` 포함). 실측 버전: langgraph 1.2.22, langgraph-checkpoint-redis 0.6.0, langchain-naver 0.1.1. 임베딩·동 1개 답은 기존 `core/clova.py` 를 계속 쓴다(HCX-005). `ChatClovaX` 는 `CLOVASTUDIO_API_KEY` 를 읽으므로 설정에서 `CLOVA_API_KEY` 를 넘긴다.

## 8. API

`POST /api/explore/chat`

요청:
```json
{
  "conversationId": null,
  "panel": "4511164500",
  "question": "여의동이랑 비교하면?",
  "criteria": {
    "chips": ["quiet"],
    "interest": { "metric": {"quiet": 0.6, "peer": 0.2}, "terrain": {"coast": 0.5}, "recent": ["4511165100"] }
  }
}
```

응답 200:
```json
{
  "conversationId": "c7f0…",
  "dongs": [{"id": "4511164500", "name": "효자2동"}, {"id": "4511163500", "name": "여의동"}],
  "intent": "compare_summary",
  "sentences": [
    {"text": "조용한 환경이 우선이면 효자2동이 맞아요.", "evidence": "조용함: 효자2동 S · 여의동 A", "source": "llm"}
  ],
  "guide": null,
  "examples": ["주말엔?", "둘이 비슷해?", "언제 가면 한산해?"]
}
```

- `conversationId` 가 없거나 만료면 서버가 새로 만든다(uuid4). 패널 동과 체크포인트의 `panel` 이 다르면 새 대화.
- 오류: 400(질문 비었음·100자 초과·칩 키 이상) · 404(패널 동 없음) · 429(throttle) · 503(그래프 없음).

## 9. 화면 (웹 짝 문서로 옮길 내용)

- 동 패널 브리핑 아래 "이 동네에 물어보기" 영역: 대화 목록, 다음 질문 예시 칩 3개, 입력창.
- 비교 중(동 2개 이상)이면 입력창 위에 기준 칩. 관심 기록 상위 항목은 켜진 채로 보여 준다.
- 문장 끝 ⓘ: 마우스 올림·키보드 포커스로 근거 줄, 터치는 탭으로 열고 닫기.
- 기다리는 동안 "생각 중…". 패널 동이 바뀌면 대화를 비운다. 대화 내용은 브라우저 메모리에만.
- `criteria.interest` 는 `features/interest` 의 `InterestProfile` 에서 만든다(지표 관심, 지형, 최근 본 동 3개).

## 12. 테스트

HCX·Redis·Neo4j 없이(가짜 채팅 함수·`InMemorySaver`·고정 그래프 결과).

- 동네 찾기: 같은 시군구 이름, 띄어쓰기 변형, 다른 시군구 → guide, 시군구 이름만 → guide, 이름 없음 → 직전 동 이어받기, 4개 이상 → 3개
- 의도: 못 찾음 + 동 이름 → 직전 의도(없으면 비교 중 compare_summary), 못 찾음 + 동 이름 없음 → 안내(비교 중이어도), 동 1개 + `compare_summary` → guide
- 축 고르기: 칩 > 지표 관심 > 지형 > 최근 본 동 > 등급 차 순서, 중복 없음
- 축별 순서·동점, 공통점 n개, 닮음 백분위 구간
- 검사: 문장 속 동 ≠ 1등 → 규칙, 문장 속 동 이름 없음·여러 개 → 규칙, 전문 용어 → 규칙, 끊긴 문장 → 규칙, 동점 축 규칙 문장
- 근거 줄이 그래프 값과 일치
- 그래프: 같은 `thread_id` 로 세 턴 이어짐, 다른 패널 → 새 대화, 체크포인터 오류 → 체크포인터 없이 재실행, 저장된 체크포인트에 질문 원문 없음
- 캐시: 비교 답 TTL 1일, 프롬프트 버전이 바뀌면 다른 키
- API: 응답 모양, 400/404/429/503, HCX 없음 → `source: rule`
