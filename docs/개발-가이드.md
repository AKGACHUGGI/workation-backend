# 개발 가이드 (backend)

흐름 · 커밋 · PR 규칙은 [workation-docs 협업 규칙](https://github.com/TEAM-SKPJC/workation-docs/blob/main/협업/협업-규칙.md) 을 따릅니다. 이 문서는 백엔드 세부 사항만 다룹니다.

## 버전

| 항목 | 버전 |
| --- | --- |
| Python | 3.14 (하한 3.12) |
| Django | 5.2 LTS |
| Django REST Framework | 3.18 |
| DB | Supabase PostgreSQL 17 (테스트는 `postgres:17`) |

정확한 버전은 `uv.lock` 이 기준입니다. 의존성 추가는 `uv add <패키지>` (개발용은 `uv add --dev`). 버전을 고른 근거는 [설계 문서](superpowers/specs/2026-11-08-django-setup-design.md) 3장.

## 커밋 전 검사

CI 와 같은 명령입니다.

```bash
uv run ruff check .
uv run ruff format --check .      # 고치려면 uv run ruff format .
docker compose up -d --wait test-db
uv run pytest
```

- ruff 는 `db/`(데이터 담당의 SQL · 생성 스크립트)와 마이그레이션 파일을 검사하지 않습니다.
- ruff format 은 마크다운 안의 파이썬 코드 블록도 포맷합니다.

## 구조

| 경로 | 내용 |
| --- | --- |
| `config/` | 설정(`settings.py`), 테스트 설정(`settings_test.py`), URL |
| `core/` | 헬스체크 `GET /api/health` |
| `regions/` | `Region`(시군구) · `Dong`(행정동) · `DongHourly`(24시간 곡선) |
| `metrics/` | `MetricDef`(지표 정의) · `Metric`(지표 값) |
| `accounts/` | 로그인: Supabase JWT 검증 · `GET` · `PATCH` · `DELETE /api/me` |
| `webapi/` | 웹 · 모바일 화면 계약 API (`/api/...`): 화면 `views.py` · 마이페이지 `me.py` · 즐겨찾기 · 팁 SQL `community.py` |
| `search/` | 자연어 검색 `POST /api/v1/search/nl` (HyperCLOVA X · CLOVA 임베딩 · pgvector) |
| `explore/` | 탐색 v6: 파생값 `derive.py` · SQL `sources.py` · 그래프 `graph.py` · Neo4j 쓰기 `graph_write.py`(명령 전용) / 읽기 `graphdb.py` · 조회 `queries.py` · 브리핑 `brief.py` · 명령 `build_explore` · `sync_graph` · `build_briefs` |
| `core/clova.py` | CLOVA Studio 호출. 키는 `.env` 의 `CLOVA_API_KEY` |
| `db/` | 스키마 SQL. **스키마의 기준** |

새 화면 API 는 해당 도메인 앱의 `serializers.py` · `views.py` · `urls.py` 에 붙이고 `config/urls.py` 에 `include` 합니다.

## 화면 API

명세는 [workation-docs 명세/api/openapi.yaml](https://github.com/TEAM-SKPJC/workation-docs/blob/main/명세/api/openapi.yaml) (0.4.0) 이 기준입니다. 경로 접두사는 `/api/v1`, id 는 공식 코드(시군구 5자리 `sigungu_code`, 행정동 10자리 `adm_code`)입니다.

| API | 화면 | 구현 |
| --- | --- | --- |
| `POST /search/nl` | W-01 자연어 검색 | `search/engine.py`: 질문 분해 → 표현 사전 매칭(유사도 0.68) → 행정동 순위 → 규칙 템플릿 사유 |
| `GET /map/scores` | W-01 지도 | `metrics/views.py`. `metric=value` 는 프리셋 가중 평균, 행정동은 소속 시군구의 시기 여유 · 숙박 성향을 씀 |
| `GET /tiers` | W-02 티어리스트 | `metrics/views.py`. 종합 점수 등급은 사분위 |
| `GET /regions/{id}` · `/regions/{id}/months` | W-03 지역 상세 | `regions/views.py` |
| `GET /dongs/{id}` | W-04 동네 프로필 | `regions/views.py`. 비슷한 동네는 pgvector `dong_feature` |

- 종합 점수 계산은 `metrics/scoring.py` 한 곳에 있습니다. 지도 · 티어 · 지역 상세가 같은 함수를 써서 화면마다 숫자가 달라지지 않습니다.
- 사진 · 팁 · 투표 · 지원사업 링크는 데이터가 없어 빈 값으로 내려줍니다.
- `CLOVA_API_KEY` 가 없거나 CLOVA 호출이 실패하면 규칙 파서와 문자열 매칭으로 대신 동작합니다 (시연 중 장애 대비).
- 웹 개발 서버(`localhost:5173`)에서 부를 수 있게 CORS 를 열어 두었습니다. 배포 도메인은 `CORS_ALLOWED_ORIGINS` 로 더합니다.
- 테스트 DB 에는 pgvector 테이블이 없어서, 자연어 검색과 비슷한 동네의 SQL 은 테스트에서 대체(monkeypatch)합니다. 실제 DB 로는 직접 실행해 확인했습니다.

## 탐색 v6 (Neo4j)

| API | 화면 | 구현 |
| --- | --- | --- |
| `GET /api/explore/sigungu/{id}/pins` | W-09 ① 시군구 핀 · 지식그래프 | `explore/queries.py` `PINS` |
| `GET /api/explore/dongs/{id}` | W-09 ② 동 패널 | `explore/queries.py` `DONG` · `FACTS` + `dong_brief` |

- Neo4j 는 Postgres 파생 표의 읽기 전용 복사본이다. 서비스 코드는 `graphdb.read`(읽기 트랜잭션)만 쓴다.
- 응답은 1시간 캐시, Neo4j 가 안 되면 마지막 응답, 그것도 없으면 503 `GRAPH_UNAVAILABLE`.
- 로컬: `scripts/explore-local.sh` (neo4j 컨테이너 + `sync_graph`). `.env` 의 Neo4j 값은 `.env.example` 기본값 그대로.
- `build_explore` · `build_briefs` 는 **공용 Supabase 에 쓰는** 월 배치다(`build_briefs` 는 CLOVA 호출 비용). 월 적재 담당만 돌리고, 돌린 뒤 팀에 알려 각자 `scripts/explore-local.sh` 를 다시 실행한다.
- 통합 테스트: `NEO4J_TEST_URI=bolt://localhost:7687 uv run pytest -m neo4j -v` (그 Neo4j 의 그래프를 테스트 그래프로 바꾼다).

## 캐시 (Redis)

- `.env` 에 `REDIS_URL` 이 있으면 Redis, 없으면 프로세스 메모리 캐시입니다. 홈 검색 · 탐색 · throttle 이 같은 Redis 를 쓰고 키 접두어로 나눕니다(`emb:` · `explore:` · `throttle_`, 앞에 `workation:1:`).
- 로컬: `docker compose up -d --wait redis` 후 `REDIS_URL=redis://localhost:6379/0`. 키 확인 `docker compose exec redis redis-cli --scan --pattern 'workation:*' | head`.
- Redis 가 죽어도 요청은 캐시 없이 진행합니다(`core/cache.py`, 경고 로그). 그 동안 throttle 은 동작하지 않습니다.
- 단위 테스트는 Redis 없이 돕니다(`config/settings_test.py` 메모리 캐시).

## 로그인 (Supabase Auth)

- 로그인·토큰 발급·갱신은 Supabase Auth 가 한다. 백엔드는 `Authorization: Bearer <access token>` 을 검증만 한다 (`accounts/jwt.py`).
- `.env`: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(계정 삭제), 레거시 HS256 프로젝트면 `SUPABASE_JWT_SECRET`.
- 로그인이 필요한 뷰는 `authentication_classes = [SupabaseJWTAuthentication]` 를 붙이고 `request.user`(AppUser 또는 None)를 본다. 다른 API 는 인증 없이 동작한다.
- `app_user` 는 첫 `GET /api/me` 에서 생긴다. `agreed_at IS NULL` 이면 웹이 온보딩(약관·닉네임)을 띄운다.
- 테스트는 `tests/supabase_tokens.py` 의 `supabase` 픽스처와 `make_token()` 을 쓴다 (실제 Supabase 불필요).

## 마이페이지 · 즐겨찾기 · 노트 (W-08 · M-05 · M-07)

계약은 workation-web `src/features/me/types.ts` · `src/features/region/types.ts`(`Note`)이고 모바일도 같은 경로를 씁니다. 뷰는 `webapi/me.py` · `webapi/views.py`, SQL 은 `webapi/community.py` 에 있습니다.

| API | 내용 |
| --- | --- |
| `GET /api/me/favorites/ids` | 하트 상태용 코드 목록 (저장한 순서) |
| `GET /api/me/favorites?month=` | 즐겨찾기 카드. `scores` 는 `/api/tier` 와 같은 값 (최근에 저장한 것부터) |
| `PUT` · `DELETE /api/me/favorites/{regions\|dongs}/{id}` | 204. 종류별 50개를 넘으면 409 `FAVORITE_LIMIT`, 없는 id 의 `PUT` 은 404 |
| `GET /api/regions/{id}/notes` · `/api/dongs/{id}/notes` | 공개 팁. `sort=helpful\|recent`, `cursor`. 로그인 없이 읽음 |
| `GET /api/me/summary` · `/api/me/tips` · `/api/me/photos` | 내 활동 요약 · 내 팁 · 내 사진 |
| `POST /api/regions/{id}/notes` · `/api/dongs/{id}/notes` | 팁 쓰기. 본문 `{body, visitMonth?}`, 201 + 만든 `Note`. 로그인 필요(401) · 없는 id · 제외 동 404 · `body` 비었거나 300자 초과 · `visitMonth` 형식 오류 400 · 1분에 3개를 넘으면 429 `TIP_RATE_LIMIT` |
| `DELETE /api/me/tips/{id}` | 204. 내 팁이 아니면 404 |

- `/api/me/*` 는 `MeAPIView`(`webapi/me.py`)를 상속합니다. 토큰이 없거나 `app_user` 가 아직 없으면 401 입니다.
- id 는 시군구 · 행정동 코드로 받고 DB 에는 `unit_id`(region_id · dong_id)로 저장합니다 (`community.unit_id`).
- 팁 쓰기는 `community.create_tip` 한 문장으로 최근 1분의 내 팁을 세고 넣습니다(`TIP_BURST_LIMIT` · `TIP_BURST_WINDOW`, DB 의 `tip.created_at` 기준 — 캐시를 쓰지 않음). `visitMonth` 는 읽기가 `2025-MM` 으로 돌려주므로 2025년 달만 받습니다.
- 팁 목록은 한 쪽에 20개이고 `nextCursor` 는 건너뛸 개수입니다. 클라이언트는 값을 그대로 돌려주기만 합니다.
- `summary.stays` 는 체류 기록 표가 없어 내 공개 팁의 시군구별 개수입니다. `voteCount` 는 투표한 대상(지역 · 동네 × 월) 수입니다.
- 아직 없는 것: 알림 설정 `/api/me/settings`(501), 도움돼요 · 투표 쓰기, 체감 투표 결과(`…/poll` 은 빈 결과), 사진 올리기.

## 모델 규칙

- 테이블은 `db/` 의 SQL 이 만듭니다. 모델은 전부 `managed = False` 이고 `migrate` 로 테이블을 만들거나 바꾸지 않습니다 ([db/README.md 스키마 변경 규칙](../db/README.md#스키마-변경-규칙)).
- 컬럼을 바꿀 때는 `db/migrations/` SQL 과 `db/schema.sql` 을 먼저 고치고, 같은 PR 에서 모델 필드를 맞춥니다.
- 모델 필드는 DB 컬럼의 부분집합이면 됩니다. DB 에 없는 필드를 넣으면 테스트가 깨집니다 (테스트 DB 가 `db/schema.sql` 로 만들어지기 때문).
- 복합 기본키 테이블(`metric`, `dong_hourly`)은 `models.CompositePrimaryKey` 를 씁니다.
- `metric.unit_id` 는 FK 가 아닙니다. 시군구 · 행정동 이름은 따로 조회해 합칩니다.
- 모델 파일을 바꾸면 `DJANGO_SETTINGS_MODULE=config.settings_test uv run python manage.py makemigrations` 로 마이그레이션 파일도 갱신해 커밋합니다 (테이블에는 영향 없음).

## 테스트

- `config/settings_test.py` 가 DB 를 로컬 테스트 Postgres(`localhost:5432`, `postgres/postgres`)로 고정합니다. `.env` 에 Supabase 가 있어도 테스트는 Supabase 에 붙지 않습니다.
- 5432 를 다른 DB 가 쓰고 있으면 `export TEST_DB_PORT=5433` 후 `docker compose up -d --wait test-db`. compose 와 테스트 설정이 같은 변수를 읽습니다. 그 밖에 `TEST_DB_HOST` · `TEST_DB_USER` · `TEST_DB_PASSWORD` 도 있습니다.
- `tests/conftest.py` 가 테스트 DB 를 만든 직후 `db/schema.sql` 을 실행합니다.

## Supabase 연결 확인 (수동)

1. `.env` 에 데이터 담당에게 받은 접속 정보를 넣습니다. **Session pooler (포트 5432)** 를 씁니다. Transaction pooler(6543) 는 쓰지 않습니다.
2. 비밀번호는 `DB_PASSWORD` 에 그대로 넣습니다. URL 이 아니라서 `@` · `!` 같은 기호를 인코딩하지 않아도 됩니다.
3. `uv run python manage.py runserver` 후 `curl localhost:8000/api/health` → `{"status":"ok","db":"ok"}`
4. 데이터 확인: `uv run python manage.py shell -c "from regions.models import Dong; print(Dong.objects.count())"` → `204`

## Docker

```bash
docker build -t workation-backend:dev .
docker run --rm -p 8000:8000 --env-file .env workation-backend:dev
```

Gunicorn gthread 워커(2 × 4 스레드)로 뜹니다. 배포 구성(Traefik · Redis)은 별도로 추가합니다.
